# Agent预约信息收集改进

## 改进概述

本次改进的核心目标是：**当Agent确定用户需要预约后，竭尽全力完善JSON所有内容**。

## 主要改进内容

### 1. 增强的系统提示 (agent_1.py)

在对话链的系统提示中明确要求：

```
【重要】一旦确定患者需要预约，你必须竭尽全力收集以下所有信息：
- 患者基本信息：姓名、年龄、性别、联系方式、身份证号
- 主诉症状：患者的主要不适
- 现病史：症状出现的时间、性质、程度、诱因、缓解因素等
- 详细症状：视力变化、眼痛、眼红、分泌物、其他症状
- 既往病史：过往的眼科疾病或其他疾病
- 用药史：正在使用或曾经使用的眼药或其他药物
- 过敏史：药物过敏、食物过敏等
- 家族史：家族中是否有眼科疾病或遗传病
- 预约信息：期望就诊时间、医生偏好、紧急程度
```

### 2. 实时缺失字段提醒

新增 `_get_missing_critical_fields()` 方法，实时检查以下关键字段是否缺失：
- 患者基本信息（姓名、年龄、性别、联系方式）
- 症状信息（主诉、现病史）
- 病史信息（既往病史、过敏史）
- 预约信息（期望时间、紧急程度）

在每次对话中，Agent会收到缺失字段的提醒，促使其主动询问。

### 3. 全面的信息提取

#### 3.1 综合信息提取 (`_extract_comprehensive_info()`)

一旦确定需要预约，对每条用户输入都使用LLM进行全面分析，提取：
- 患者基本信息（姓名、年龄、性别等）
- 症状相关（症状描述、持续时间、严重程度）
- 病史相关（既往病史、用药史、过敏史、家族史）
- 预约相关（期望时间、紧急程度、医生偏好）

#### 3.2 对话历史全面提取 (`extract_from_conversation()`)

在对话完成时，使用LLM分析整个对话历史，确保没有遗漏任何信息。

#### 3.3 症状细节智能填充 (`_fill_symptom_details()`)

自动将症状描述分类填充到结构化字段：
- vision_change（视力变化）
- eye_pain（眼痛）
- redness（眼红）
- discharge（分泌物）
- other（其他症状）

### 4. 更严格的阶段推进条件

修改 `_update_stage()` 方法，提高阶段推进门槛：

- **患者信息收集阶段**：至少收集3项基本信息（原来是2项）
- **眼科分诊阶段**：至少收集2项症状相关信息
- **病史采集阶段**：至少收集2项病史信息
- **预约确认阶段**：预约信息齐全且关键缺失项不超过2个

### 5. 优化的阶段提示

每个阶段的提示更加明确，清楚说明需要收集哪些信息：

```python
ConversationStage.PATIENT_INFO_COLLECTION: 
  "【重要】收集患者基本信息。必须询问并记录：姓名、年龄、性别、联系方式（手机号）。可以一次询问多项。"

ConversationStage.MEDICAL_HISTORY: 
  "【重要】采集完整病史。必须询问：既往眼科疾病或其他疾病、正在使用的药物、药物过敏史、家族遗传病史。即使患者说'无'也要明确记录。"
```

### 6. 增强的信息提取能力

改进了多个提取方法：
- `_extract_patient_info_with_llm()`：更准确的患者信息提取
- `_extract_appointment_info()`：新增医生偏好提取
- `_extract_comprehensive_info()`：全新的综合信息提取方法

## 技术实现细节

### 数据流程

1. **用户输入** → 记录对话历史
2. **信息提取** → 如果已确定需要预约，调用全面信息提取
3. **生成回复** → 使用缺失字段提醒Agent
4. **阶段更新** → 根据收集到的信息推进阶段
5. **完成处理** → 最终全面提取+症状细节填充

## 预期效果

通过以上改进，Agent将：

1. ✅ **更主动**：明确知道需要收集哪些信息，主动询问缺失项
2. ✅ **更完整**：多层次的信息提取确保不遗漏任何重要信息
3. ✅ **更准确**：使用LLM智能提取和分类信息
4. ✅ **更系统**：按照医疗问诊流程系统地收集信息
5. ✅ **更严格**：更高的完成标准，确保信息质量

## 使用建议

1. **测试时**：观察Agent是否在每个阶段主动询问相关信息
2. **检查输出**：使用 `get_patient_data_json()` 查看最终收集的完整数据
3. **调整阈值**：如需要更严格或更宽松的收集标准，可调整 `_update_stage()` 中的条件

## 注意事项

- LLM提取可能会消耗更多token，但能显著提高信息完整性
- 如果提取失败，系统会静默处理，不影响正常流程
- "无"或"没有"等否定回答也会被记录，确保信息的完整性
