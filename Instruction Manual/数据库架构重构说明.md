# 数据库架构重构说明

## 修复日期
2025-11-16

## 问题诊断

### 原架构的问题
当前数据库设计将"用户"和"病例"混在一起：
- `patient` 表的一条记录既代表"一个人"，又代表"一次就诊"
- **问题1**：同一个人多次就诊会产生多个 `Patient_ID`
- **问题2**：无法直接识别用户身份，需要通过 `Phone_Number` 关联
- **问题3**：用户基本信息（姓名、性别）和病例信息（主诉、诊断）混在一起

### 用户反馈
> "Patient_ID是用户唯一id吧？每次应该有病例id与之关联，预约id与病例id关联"

**用户的理解是正确的！** ✅

## 正确的数据库架构

### 三层关系模型

```
用户表 (patient)
    ↓ 1:N
病例表 (medical_record)
    ↓ 1:N
预约表 (appointment)
```

### 1. 用户表 (patient)
**一条记录 = 一个人（用户基本信息）**

| 字段 | 说明 | 备注 |
|------|------|------|
| Patient_ID | 用户ID（主键） | 唯一标识一个人 ✅ |
| Name | 姓名 | 基本信息 |
| Gender | 性别 | 基本信息 |
| Phone_Number | 手机号 | **唯一约束** |
| Age | 年龄 | 基本信息 |
| Address | 地址 | 基本信息 |
| Insurance_Card_Number | 医保卡号 | 医保信息 |

**特点**：
- `Patient_ID` 是用户的唯一标识
- 同一个人只有一条记录
- `Phone_Number` 有唯一约束
- 不包含就诊相关信息

### 2. 病例表 (medical_record)
**一条记录 = 一次就诊（病例信息）**

| 字段 | 说明 | 备注 |
|------|------|------|
| Medical_Record_ID | 病例ID（主键） | 唯一标识一次就诊 ✅ |
| Patient_ID | 用户ID（外键） | 关联到 patient 表 |
| Visit_Card_Number | 就诊卡号 | 每次就诊的卡号 |
| Visit_Date | 就诊日期 | 本次就诊时间 |
| Chief_Complaint | 主诉 | 本次症状 |
| Diagnosis | 诊断 | 本次诊断结果 |
| Medical_History | 既往病史 | 历史病史 |
| Allergy_History | 过敏史 | 过敏信息 |

**特点**：
- `Medical_Record_ID` 是病例的唯一标识
- 同一个用户可以有多条病例记录
- 每次就诊创建一条新记录
- 通过 `Patient_ID` 外键关联到用户

### 3. 预约表 (appointment)
**一条记录 = 一次预约**

| 字段 | 说明 | 备注 |
|------|------|------|
| Appointment_ID | 预约ID（主键） | 唯一标识一次预约 ✅ |
| Medical_Record_ID | 病例ID（外键） | 关联到 medical_record 表 |
| Patient_ID | 用户ID（外键，冗余） | 关联到 patient 表 |
| Doctor_ID | 医生ID（外键） | 关联到 doctor 表 |
| Appointment_Time | 预约时间 | 预约的具体时间 |
| Appointment_Status | 预约状态 | 已预约/已完成/已取消 |

**特点**：
- `Appointment_ID` 是预约的唯一标识
- 通过 `Medical_Record_ID` 关联到具体病例
- 同一个病例可以有多个预约（如复诊）
- `Patient_ID` 作为冗余字段便于查询

## 数据关系示例

### 示例：张三两次就诊

#### 1. 用户表 (patient)
| Patient_ID | Name | Phone_Number |
|------------|------|--------------|
| 1 | 张三 | 13900000001 |

#### 2. 病例表 (medical_record)
| Medical_Record_ID | Patient_ID | Visit_Date | Chief_Complaint | Diagnosis |
|-------------------|------------|------------|-----------------|-----------|
| 101 | 1 | 2025-11-10 | 眼睛干涩 | 干眼症 |
| 102 | 1 | 2025-11-15 | 视力模糊 | 待诊断 |

#### 3. 预约表 (appointment)
| Appointment_ID | Medical_Record_ID | Patient_ID | Doctor_ID | Appointment_Time |
|----------------|-------------------|------------|-----------|------------------|
| 1001 | 101 | 1 | 1 | 2025-11-11 09:00 |
| 1002 | 102 | 1 | 2 | 2025-11-17 14:00 |

**查询逻辑**：
- 查询张三的所有病例：`WHERE Patient_ID = 1`
- 查询张三的所有预约：`WHERE Patient_ID = 1`
- 查询某个病例的预约：`WHERE Medical_Record_ID = 102`

## 实施方案

### 方案A：迁移现有数据
如果数据库已有数据，需要数据迁移：

1. 创建新表结构（`init_database_v2.sql`）
2. 数据迁移脚本：
   - 从旧 `patient` 表提取用户信息（按 `Phone_Number` 去重）
   - 将旧 `patient` 表数据转为 `medical_record` 表
   - 更新 `appointment` 表的外键关联
3. 删除旧表
4. 重命名新表

### 方案B：重新初始化数据库（推荐）
如果是开发阶段，直接使用新结构：

```bash

# 执行新的数据库脚本
mysql -u root -p < database/init_database_v2.sql
```

## 代码修改计划

### 1. AppointmentService 修改

**当前逻辑**：
```python
def create_patient(patient_data):
    # 每次创建新的 patient 记录（错误）
    patient_id = insert_into_patient(...)
    return patient_id
```

**修改后逻辑**：
```python
def create_or_get_patient(patient_data):
    """创建或获取用户"""
    phone = patient_data['patient_info']['contact']
    
    # 检查用户是否存在
    patient = db.query("SELECT * FROM patient WHERE Phone_Number = %s", phone)
    
    if patient:
        patient_id = patient['Patient_ID']
    else:
        # 首次用户，创建 patient 记录
        patient_id = insert_into_patient(...)
    
    return patient_id

def create_medical_record(patient_id, patient_data):
    """创建病例记录"""
    # 每次就诊都创建新的病例记录
    medical_record_id = insert_into_medical_record(...)
    return medical_record_id

def create_appointment(medical_record_id, patient_id, doctor_id, ...):
    """创建预约记录"""
    appointment_id = insert_into_appointment(...)
    return appointment_id
```

### 2. UserHistoryService 修改

**查询用户历史**：
```python
def get_user_history(patient_id):
    """查询用户的所有病例和预约"""
    # 查询用户基本信息
    patient = db.query("SELECT * FROM patient WHERE Patient_ID = %s", patient_id)
    
    # 查询该用户的所有病例
    records = db.query("SELECT * FROM medical_record WHERE Patient_ID = %s", patient_id)
    
    # 查询该用户的所有预约
    appointments = db.query("SELECT * FROM appointment WHERE Patient_ID = %s", patient_id)
    
    return {
        'patient': patient,
        'medical_records': records,
        'appointments': appointments
    }
```

### 3. HealthAgent 修改

**初始化时加载用户历史**：
```python
def __init__(self, phone_number: str):
    """通过手机号初始化"""
    self.phone_number = phone_number
    
    # 查询用户ID
    patient = db.query("SELECT Patient_ID FROM patient WHERE Phone_Number = %s", phone_number)
    self.patient_id = patient['Patient_ID'] if patient else None
    
    # 加载用户历史
    if self.patient_id:
        self.history = UserHistoryService().get_user_history(self.patient_id)
```

## 优势对比

❌ 同一个人多个ID  
❌ 用户信息冗余存储

❌ 概念混淆（人 vs 病例）

✅ 一个人一个ID  
✅ 用户信息统一管理  
✅ 轻松查询用户的所有病例  
✅ 概念清晰（用户→病例→预约）  
✅ 符合医疗信息系统规范

## 总结

用户的理解是完全正确的！正确的架构应该是：
- **Patient_ID** = 用户唯一标识（一个人）
- **Medical_Record_ID** = 病例唯一标识（一次就诊）
- **Appointment_ID** = 预约唯一标识（一次预约）

这样的设计符合医疗信息系统的标准，也更符合实际业务逻辑。
