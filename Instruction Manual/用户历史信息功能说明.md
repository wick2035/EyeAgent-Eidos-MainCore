# 用户历史信息加载功能说明

## 功能概述

本次更新实现了用户历史信息的自动加载功能，使AI智能体能够在对话开始前读取用户的历史就诊记录，提供更加个性化和连续的医疗咨询服务。

## 主要特性

### 1. 自动加载历史信息
- 在创建 `HealthAgent` 时传入 `user_id` 参数
- 首次对话时自动从数据库读取用户历史信息
- 无需手动调用，完全自动化

### 2. 历史信息包含
- **基本信息**：姓名、年龄、性别、联系方式、就诊卡号
- **病史信息**：既往病史、过敏史、家族史
- **历史病例**：过往就诊记录、主诉、诊断结果
- **历史预约**：预约时间、医生信息、预约状态

### 3. 智能预填充
- 老用户的基本信息自动预填充到数据处理器
- 病史信息（既往病史、过敏史、家族史）自动加载
- AI助手无需重复询问已有的信息
- 减少用户重复输入，提升体验

### 4. 个性化对话
- AI助手参考历史就诊记录提供建议
- 可以对比本次症状与历史症状
- 对老用户更加自然和友好的对话方式

## 使用示例

### 示例 1：新用户
```python
from agents.agent_1 import HealthAgent

# 不提供 user_id，按新用户处理
agent = HealthAgent()
```

```python
from agents.agent_1 import HealthAgent

agent = HealthAgent(user_id=1)
```

```python
from flask import Flask, request, session

    user_id = session.get('user_id')  # 从session获取

    if 'agent' not in session:
        agent = HealthAgent(user_id=user_id)
        # 存储到session或缓存中
    
    response = agent.chat(request.json['message'])
    return {'response': response}
```

## 数据库要求

系统依赖以下数据库表：

### 1. patient 表
- `Patient_ID`: 患者唯一标识（主键）
- `Name`: 姓名
- `Gender`: 性别
- `Age`: 年龄
- `Phone_Number`: 联系方式
- `Visit_Card_Number`: 就诊卡号
- `Chief_Complaint`: 主诉
- `Diagnosis`: 诊断
- `Medical_History`: 既往病史
- `Allergy_History`: 过敏史
- `Family_History`: 家族史
- `Visit_Date`: 就诊日期

### 2. appointment 表
- `Appointment_ID`: 预约ID（主键）
- `Patient_ID`: 患者ID（外键）
- `Doctor_ID`: 医生ID（外键）
- `Appointment_Time`: 预约时间
- `Appointment_Status`: 预约状态
- `Description`: 描述

### 3. doctor 表
- `Doctor_ID`: 医生ID（主键）
- `Name`: 医生姓名
- `Title`: 职称
- `Specialty`: 专科
- `Hospital_Area`: 所属院区

## 工作流程

```
1. 用户登录 → 获取 user_id
                ↓
2. 创建 HealthAgent(user_id) 
                ↓
3. 首次调用 chat()
                ↓
4. 自动触发 _load_user_history()
                ↓
5. 查询数据库：
   - 基本信息
   - 历史病例
   - 历史预约
                ↓
6. 预填充已知信息到 data_handler
                ↓
7. 格式化历史信息文本
                ↓
8. 传递给 LLM 作为上下文
                ↓
9. AI 参考历史信息生成回复
```

## 优势

### 1. 用户体验提升
- **减少重复输入**：老用户无需重复提供基本信息
- **连续性对话**：AI能够参考历史记录
- **个性化服务**：根据历史症状提供针对性建议

### 2. 信息完整性
- 自动预填充已知信息，减少遗漏
- 保持历史记录的连续性
- 便于医生了解患者完整病史

### 3. 效率提升
- 减少信息收集时间
- 加快预约流程
- 提高咨询质量

## 注意事项

### 1. 数据隐私
- 确保用户ID验证正确
- 不要将用户历史信息泄露给其他用户
- 遵守医疗数据隐私法规

### 2. 性能优化
- 历史信息仅在首次对话时加载一次
- 避免重复查询数据库
- 考虑添加缓存机制

### 3. 错误处理
- 如果数据库查询失败，不影响正常对话
- 新用户按正常流程处理
- 记录错误日志便于排查
