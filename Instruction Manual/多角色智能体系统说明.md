# 多角色智能体系统使用说明

## 功能概述

本系统实现了基于角色的多智能体自动路由系统，支持医生和患者两种角色，并根据对话内容自动选择合适的Agent（健康咨询Agent或报告分析Agent）。

## 核心功能

### 1. 角色系统

#### 患者角色（Patient）
- **权限**：
  - ✅ 可以进行健康咨询
  - ✅ 可以查看自己的历史报告
  - ✅ 可以分析病情趋势
  - ✅ 可以对比历史记录
  - ❌ **不能生成新报告**

#### 医生角色（Doctor）
- **权限**：
  - ✅ 可以进行健康咨询和问诊
  - ✅ 可以查看任何患者的历史报告
  - ✅ 可以分析病情趋势
  - ✅ 可以对比历史记录
  - ✅ **可以生成病例报告**

### 2. 智能Agent路由

系统包含两个Agent：

#### Agent 1 - 健康咨询Agent（HealthAgent）
负责处理：
- 症状咨询
- 健康评估
- 医生预约
- 分诊问诊
- 病史采集

#### Agent 2 - 报告分析Agent（ReportAgent）
负责处理：
- 查看历史报告
- 生成病例报告（仅医生）
- 分析病情趋势
- 对比就诊记录
- 回答历史问题

### 3. 意图识别

系统会根据用户的对话内容自动判断应该使用哪个Agent：

**触发健康咨询Agent的关键词：**
- 症状相关：不舒服、疼、痛、难受、模糊、红肿等
- 预约相关：预约、挂号、看病、就诊等
- 咨询相关：咨询、问诊、检查、治疗等

**触发报告分析Agent的关键词：**
- 报告相关：报告、病例、历史、记录、档案
- 分析相关：分析、对比、比较、趋势、变化
- 查询相关：查看、查询、上次、之前、以前

## 使用流程

### 启动服务

```bash
cd D:\Agent\pythonProject1
python main.py
```

服务将在 http://127.0.0.1:8000 启动

### 前端使用

1. 打开浏览器访问：http://127.0.0.1:8000

2. **选择身份**：
   - 在顶部选择"患者"或"医生"身份
   - 切换身份时会自动重置会话

3. **选择用户**（可选）：
   - 患者身份：只能选择自己
   - 医生身份：可以选择任何患者

4. **开始对话**：
   - 输入您的问题或需求
   - 系统会自动选择合适的Agent
   - 右下角状态栏会显示当前使用的Agent

### API使用

#### 对话接口

```http
POST /api/chat
Content-Type: application/json

{
  "message": "用户消息",
  "session_id": "会话ID（可选）",
  "role": "patient 或 doctor",
  "user_id": 用户ID（可选）,
  "phone_number": "手机号（可选）"
}
```

#### 响应格式

```json
{
  "response": "AI回复内容",
  "session_id": "会话ID",
  "is_completed": false,
  "stage": "当前阶段",
  "agent_type": "health 或 report"
}
```

## 使用示例

### 示例1：患者健康咨询

```python
import requests

# 患者咨询症状
response = requests.post("http://127.0.0.1:8000/api/chat", json={
    "message": "医生您好，我最近眼睛有点模糊",
    "role": "patient"
})

# 系统会自动使用 HealthAgent (agent_type="health")
```

### 示例2：患者查看历史

```python
# 患者查看历史报告
response = requests.post("http://127.0.0.1:8000/api/chat", json={
    "message": "我想查看一下我的历史病例报告",
    "role": "patient"
})

# 系统会自动切换到 ReportAgent (agent_type="report")
```

### 示例3：患者尝试生成报告（被拒绝）

```python
# 患者尝试生成报告
response = requests.post("http://127.0.0.1:8000/api/chat", json={
    "message": "请帮我生成一份病例报告",
    "role": "patient"
})

# 系统会拒绝：
# "抱歉，只有医生才能生成新的病例报告。患者可以查看和分析现有的报告..."
```

### 示例4：医生生成报告（允许）

```python
# 医生生成报告
response = requests.post("http://127.0.0.1:8000/api/chat", json={
    "message": "我想生成一份病例报告",
    "role": "doctor",
    "user_id": 1  # 指定患者ID
})

# 系统会允许并引导医生完成生成报告流程
```

### 关键组件

1. **IntentDetector（意图识别器）**
   - 位置：`utils/intent_detector.py`
   - 功能：分析用户消息，判断应使用哪个Agent
   - 方法：关键词匹配 + LLM判断

2. **AgentManager（Agent管理器）**
   - 位置：`agents/agent_manager.py`
   - 功能：创建和管理Agent实例，支持动态切换

3. **权限控制**
   - 前端：身份选择和UI提示
   - 后端：意图识别中的权限检查
   - Agent：ReportAgent中的权限验证

## 权限控制机制

### 三层权限控制

1. **意图识别层**（`utils/intent_detector.py`）
   - 检测到患者尝试生成报告时，直接阻止并返回提示

2. **Agent层**（`agents/agent_2.py`）
   - 在 `generate_report()` 方法中检查角色
   - 如果是患者角色，拒绝执行并返回友好提示

3. **提示词层**（Agent的Prompt）
   - 在对话模板中明确说明权限限制
   - 让AI理解不同角色的权限差异

## 注意事项

1. **切换身份会重置会话**：当您切换患者/医生身份时，系统会自动重置会话以避免混乱

2. **Agent自动切换**：系统会根据对话内容自动切换Agent，无需手动选择

3. **权限提示**：当尝试执行无权限的操作时，系统会给出友好的提示

4. **历史信息加载**：
   - 推荐使用手机号（可获取所有历史记录）
   - 使用Patient_ID只能获取单个病例

5. **意图识别准确性**：
   - 使用明确的关键词可以提高识别准确率
   - 模糊的表述可能导致Agent选择不准确

## 常见问题

### Q1: 如何确认当前使用的是哪个Agent？
A: 查看页面右下角状态栏的"当前Agent"字段

### Q2: 患者为什么不能生成报告？
A: 这是基于实际医疗场景的权限设计，病例报告应由医生生成

### Q3: Agent切换会丢失对话历史吗？
A: 不会，对话历史保存在会话中，但不同Agent有各自的处理逻辑

### Q4: 如何强制使用特定的Agent？
A: 系统基于意图自动路由，使用相关关键词可以引导系统选择特定Agent

### Q5: 意图识别不准确怎么办？
A: 使用更明确的关键词，或在 `utils/intent_detector.py` 中调整规则

```python

        'blocked': True
```

### 调整意图识别关键词

修改 `utils/intent_detector.py` 中的关键词列表：

```python
HEALTH_KEYWORDS = [
    '症状', '不舒服', # 添加更多关键词
]

REPORT_KEYWORDS = [
    '报告', '病例', # 添加更多关键词
]
```

### 添加新的Agent

1. 在 `agents/` 目录创建新Agent类
2. 在 `agent_manager.py` 中注册
3. 在 `intent_detector.py` 中添加识别规则
